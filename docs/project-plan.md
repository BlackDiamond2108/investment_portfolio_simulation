# Устройство проекта

Приложение реализует экономическую игру из задания «Система управления
инвестиционным портфелем». Оно работает локально, без сервера и реальных котировок.
Основные части: расчётная модель, одно окно Qt Widgets и JSON-сохранения.

Всего 20 файлов исходного проекта и два файла документации LaTeX/PDF. Виджеты вкладок создаются в MainWindow.cpp;
их контейнеры и общая компоновка находятся в MainWindow.ui. Отдельных классов
диалогов нет: редактор одного инструмента использует локальный QDialog.

## Зависимости и владение

```text
main → MainWindow → Simulation → Portfolio
                ↘ DashboardWidget (данные для отображения и сигналы действий)
                ↘ GameStorage → GameState
```

MainWindow владеет Simulation. Simulation владеет единственным GameState
и генератором mt19937_64. Portfolio выполняет операции над переданными данными.
GameStorage использует Qt Core для JSON и файлов; игровой код не зависит от Qt.
Окно читает state()/statistics(), но меняет игру только через команды Simulation.

Цели CMake: `portfolio_core`, `portfolio_storage`, `portfolio_ui`,
`portfolio_simulator` и `simulation_tests`. Все операции идут в GUI-потоке:
для небольшого портфеля и 30 месяцев отдельные потоки не нужны.

## Основные сценарии

**Новая игра:** collectConfig → validateConfig → start. Стартовый капитал
становится свободными RUB. trade создаёт позиции; confirmInitialAllocation
фиксирует стартовую оценку. Можно не вкладывать часть денег.

**Сделка:** форма → previewTrade → проверка на копии → предварительный остаток.
Подтверждение → trade → Portfolio.executeTrade → оплата обязательств из выручки
→ refreshView. Номер строки таблицы не является идентификатором позиции.

**Месяц:** nextMonth обновляет рынок, начисляет доход и налог и создаёт PendingMonth.
Фаза AwaitingFlows требует подтверждения поступлений/возвратов. applyFlows переводит
в Restructuring. Затем доступны сделки и finishMonth. Кнопки отражают фазу,
но движок повторно проверяет каждую команду. Повторный клик не дублирует расчёт.
На месяце M разрешены только продажи для расчётов, после чего партия завершается.

**Завершение:** finalizeReport сохраняет текущий месяц ровно один раз,
включая досрочное закрытие и банкротство. Итоговые доходность и просадка считаются
по закрытым месяцам. Текущий незакрытый доход виден отдельной строкой истории.

**Сохранение:** exportState → GameStorage.save → QSaveFile. Загрузка сначала
полностью читает и проверяет отдельный кандидат, затем restoreState заменяет
игру вместе с RNG. Ошибка не разрушает прежнюю партию.

## Формат сохранения

JSON: `schemaVersion: 1` и объект `state`. Все поля структур перечислены в
GameStorage.cpp одной общей таблицей для чтения и записи. Money, Quantity,
ID и seed записаны десятичными строками, enum — стабильными именами.
Проверяются обязательные поля, типы, диапазоны, уникальность ID, ссылки,
фаза, история, статистика и арифметика отчётов. Лимит файла — 10 МиБ.

Сохраняются PendingMonth, предложенные потоки и полное состояние RNG.
Совпадение продолжения гарантируется в том же окружении стандартной библиотеки;
одинаковые результаты между разными реализациями случайных распределений не обещаются.

## Работа вдвоём и проверка требований

Расчётная основа участника 1 сохранена и интегрирована с интерфейсом/хранилищем.
При интеграции уточнены проверки переполнения, восстановление состояния и расчёты
при закрытии фонда; соответствующие случаи закреплены тестами.

Перед параллельными изменениями согласовать GameTypes.h и сигнатуры методов.
За правку общих CMakeLists.txt и SimulationTests.cpp назначать ответственного
на конкретную задачу; не создавать новый слой ради разделения ответственности.

Покрытые требования: все четыре класса вложений и валютные вклады; несколько
позиций одного вида; настраиваемые капитал/M/налог/рынок; ручные сделки;
ручные и автоматические паи; доход по позициям; текущие условия рынка;
месячные отчёты и итоговая статистика. Сохранения и seed добавлены для удобства.

Основные тесты: configBounds, fixedDeposit, maturity, trades, flows, liquidity,
market, fullGame, saveLoad, windowGame, terminalReports, invalidRestores,
overflowAndAtomicity, automaticFlowsContract, bondAndCurrencyIncome, windowPersistence.
windowGame проходит 12 и 30 месяцев через элементы настоящего окна.

## Визуальный обзор

DashboardWidget — отдельный виджет интерфейса: хранит только снимок данных отображения,
не изменяет Simulation и не делает финансовых проводок. Четыре небольших внутренних
виджета QPainter реализуют динамику капитала/прибыли, кольцевую диаграмму,
шкалу месяцев и горизонтальные полосы месячных потоков. Дополнительных библиотек нет.

Источники данных: MonthReport.navEnd/netProfit для закрытых месяцев,
GameStatistics.finalNav и PendingMonth для текущей предварительной точки,
Portfolio.valuePosition для структуры активов. Переход месяца из промежуточного
в закрытый заменяет точку, а не добавляет дубль. Прибыль не содержит приток денег.
В проценты кольцевой диаграммы входят активы до вычета долгов; обязательства
показываются отдельной карточкой. Нулевая и единственная точки обрабатываются явно.

Переключение периода и режима графика не меняет игру. Наведение показывает точные суммы,
клик отправляет monthRequested в окно и открывает отчёт. Продажа из карточки отправляет
positionRequested с устойчивым ID, а не с номером строки. Кнопка следующего шага вызывает
существующие команды Simulation через MainWindow. Анимация — только раскрытие графика,
новые котировки между месяцами не генерируются.

«Открыть пример» создаёт временную Simulation, размещает деньги в шесть позиций,
проводит шесть месяцев с seed=42 и автоматическими потоками. Только после успешного
расчёта этот кандидат заменяет активную игру с обычной проверкой несохранённых изменений.
Пример можно продолжать и сохранять; это не набор вручную нарисованных данных.

Проверки dashboardPresentation и dashboardExample дополнительно проверяют суммы графика,
структуру активов, убыток, влияние притока, переход предварительной точки в закрытую,
сброс при новой игре, открытие отчёта по клику и продолжение примера через кнопки.
Схема сохранений и доменные расчёты при добавлении визуализации не изменены.

Экспорт отчёта остаётся возможным дальнейшим расширением.


Навигация вынесена в отдельный QTabBar над показателями фонда и связана с QTabWidget
в обе стороны. Поэтому появление показателей на других страницах не сдвигает вкладки.
Числовые поля используют скрытые кнопки стрелок, а настройки на узком окне переходят в одну колонку.
Карточка срочного вклада открывает справку о сроке и автоматическом погашении;
досрочные финансовые операции при этом не добавляются. Проверка
navigationAndDepositDetails покрывает стабильность координат навигации,
доступность полей на компактном окне и просмотр условий без изменения партии.
