# Предлагаемые правила учебной модели (не юридические/биржевые правила)

## Время и старт
Начальный месяц 0. M целое 12..30. Сначала капитал полностью в RUB; игрок собирает
портфель, может оставить cash. Начальная цена пая 1000 RUB, число паёв = капитал/1000.
Капитал может быть любым положительным числом копеек в допустимом диапазоне;
дробные паи не требуют кратности капитала 1000 RUB.
После распределения фиксируется стартовый NAV. Операции проводятся в конце каждого месяца.
Открытый в конце t вклад начинает зарабатывать в t+1; месяц погашения t+срок.

## Валюта и стоимость
Базовая валюта RUB. Курс: RUB за 1 единицу иностранной валюты. Отдельных валютных
кошельков в первой версии нет: покупка/погашение конвертируются по текущему курсу без спреда.
NAV = RUB cash + сумма оценок позиций в RUB - непогашенные обязательства.
Деньги хранить в минимальных единицах валюты, округлять общими функциями GameTypes.h.
Произведения проверять на переполнение; проценты рассчитывать с достаточной промежуточной
точностью и округлять при проводке. Паи/металлы хранить в фиксированных дробных единицах.

## Инструменты
Депозит: principal в валюте, ставка зафиксирована на открытии, простой процент
principal * annualRate / 12 за каждый полный месяц. Процент накапливается в стоимости,
при погашении principal + accruedInterest переводятся в RUB cash и позиция удаляется.
Проценты не капитализируются; закрытие до срока запрещено. Новое предложение банка
не меняет открытые договоры; после погашения игрок может открыть новый вклад.
Облигация: упрощённая покупка по номиналу плюс начисленный купон; фиксированный годовой
купон начисляется ежемесячно, выплата каждые couponPeriodMonths и в срок погашения.
Котировка продажи = номинал + накопленный купон, рыночный процентный риск не моделируется.
Покупатель платит накопленный купон, поэтому следующая выплата не целиком его прибыль.
Купонный календарь и срок принадлежат инструменту; погашенные выпуски недоступны для покупки.
Акция/металл: оценка количество * цена. Доход только изменение цены, без дивидендов
в первом варианте. У акций могут быть разные диапазоны риска. Металл учитывать в граммах.
Доходность акции в исходном задании не задаёт явного требования дивидендной модели;
если её потребуют, добавить отдельную денежную выплату и тест против двойного учёта.

## Случайный рынок
Для каждой акции/металла: P_t = P_(t-1) * (1 + U[minChange, maxChange]).
Аналогично изменяются валютные курсы. Нижняя граница > -1; после округления цена
не меньше минимального денежного шага. Распределение равномерное — выбранное допущение.
Для новых депозитных предложений ставка меняется на случайное число процентных пунктов
из своего диапазона и ограничивается настроенными minRate/maxRate. Вклад сохраняет ставку.
Порядок обхода инструментов фиксировать по ID, чтобы не зависеть от hash-map.
Настройки диапазонов можно различать по инструментам. Нулевой диапазон отключает случайность.

## Месяц и налог
A0 = NAV в начале месяца после прошлой реструктуризации.
Обновить рынок, начислить фиксированный доход, погасить истёкшие инструменты.
A1 = NAV до нового налога и до потоков; profit = A1 - A0.
Доход каждой позиции включает проценты/купон/переоценку, также по закрывшимся в этом месяце.
Сумма статей равна profit с явно выделенной строкой округления при необходимости.
Tax = round(max(profit, 0) * taxRate). Переноса убытков нет.
Налог включает нереализованную переоценку: упрощение для задания, не реальное налогообложение.
При начислении tax вычесть деньги либо создать налоговое обязательство, уменьшающее NAV.
При погашении обязательства cash и долг уменьшаются одновременно, NAV повторно не уменьшается.
NetProfit = profit - tax; returnNet = NetProfit/A0; returnGross = profit/A0.
При A0 <= 0 доходность не определена, партия завершается с причиной неплатёжеспособности.

## Паи и потоки
После налога до потоков: unitPrice = NAV / unitsOutstanding. Эту цену фиксировать на месяц.
Ручной ввод: сумма новых поступлений и количество возвращаемых паёв (0 разрешён).
В автоматическом режиме: d = clamp(k * returnNet + U[-noise, noise], -maxOut, maxIn).
k >= 0; noise >= 0; maxOut в [0,1]; maxIn >= 0, значения проверять на конечность.
Если d >= 0, запрос поступления = NAV*d, возврат 0. Если d < 0, запрос возврата
= unitsOutstanding*(-d), поступление 0. Это простая зависимость спроса от результатов.
Автозапрос вычислить один раз и сохранить, в ручном режиме rng для потоков не продвигать.
Сначала выпуск новых паёв: unitsIssued = floorToUnitPrecision(inflow/unitPrice).
Фактически принять только стоимость выпущенных паёв, денежную разницу оставить вне фонда
и явно показать в предварительном расчёте. Затем возврат <= числа доступных паёв.
Возвращаемые паи погасить один раз; выплатить cash либо создать долг пайщикам.
Потоки не включать в прибыль и проценты доходности. Обязательства уменьшают NAV сразу.
Контрольное равенство: конечный NAV = A0 + NetProfit + acceptedInflow - redemptionValue
с учётом явно учтённого округления сделок. Дальнейшая оплата долга не считается новым оттоком.
Если все паи погашены, не делить на ноль: после расчёта обязательств завершить партию
как закрытие фонда. Если деньги ещё в ликвидных активах, оставить возможность
продажи для расчёта с пайщиками; при недостаточной ликвидности зафиксировать
неплатёжеспособность. При NAV <= 0 и оставшихся паях — завершить с причиной банкротства.

## Реструктуризация и ликвидность
Покупки только на свободные RUB, без долгов. Продажи — по текущему рынку, без комиссий,
кроме явно показанной разницы округления. Из поступивших денег сначала оплатить налог,
затем обязательства пайщикам. Игрок сам выбирает продаваемые активы.
При долгах следующего месяца нет; если cash + реализуемые активы недостаточны для долгов
и срочные депозиты ещё заблокированы, зафиксировать неплатёжеспособность и завершить игру.
Неликвидные вклады не продавать автоматически, долги не скрывать. При достаточной ликвидности
оставить игрока в Restructuring до продажи активов и оплаты.

## Конец и статистика
После M-го месяца рассчитать доход, налог и потоки; разрешить продажи для оплаты долгов,
новые покупки запретить. Завершить после выплат. Оставшиеся позиции оценить по текущим
правилам; принудительной ликвидации нет, незавершённый вклад учитывается с процентами.
Вывести конечный NAV, чистую прибыль суммой по месяцам, поток денег, налоги, паи.
Доходность всей игры: product(1 + returnNet_t) - 1, а не (NAV_end/NAV_start - 1).
Индекс доходности стартует с 1; просадка = max(1 - index_t / runningPeak).
Не вычислять сравнимую доходность для месяцев с неположительным начальным NAV.
Рост капитала, прибыль и доходность — три разных показателя.

## Точность и отображение

Цена пая в этой учебной модели хранится в копейках и округляется вниз при
вычислении NAV/число паёв. Выпускаемое количество паёв округляется вниз до 1e-6;
принимаемая сумма и выплата тоже усекаются до копейки. Остаток поступления не
принимается в фонд и показывается на вкладке операций. Поэтому, например,
из запрошенных 1000 RUB может быть фактически принято 999.99 RUB.
Это явное упрощение; для реального учёта требуется более точная цена пая.

Итоги и накопленная доходность в верхней панели относятся к закрытым месяцам.
В текущем месяце предварительные суммы и доход каждой позиции доступны в истории.
Строка отчёта сохраняется и при досрочном завершении. Количество проданных и
погашенных паёв в итогах не включает выпуск стартовых паёв.

Каталог новой игры включает как минимум RUB-вклад, валютный вклад, две акции,
металл и облигацию; в портфеле при этом можно держать любые из них или только деньги.
Максимальный срок отдельного инструмента ограничен 1200 месяцами для безопасной
проверки дат. В редакторе интерфейса доступен диапазон до 360 месяцев.
